# 内部 Agent 文件注释

本说明按调用顺序注释备份文件。下文路径均相对于 `源文件/`；源码副本保持原样，便于核验和回拷。

## 1. 浏览器入口

- `cinema-ticketing-frontend/src/chat/CinemaAssistant.tsx`：聊天界面和模式状态。用户点击“转接实时 Agent”后调用 Java `/api/ai/handoff` 取得限时凭证；发送消息时把当前会话 ID、问题、模式和凭证交给网关。前端只暂存凭证，不负责判定订单归属。
- `cinema-ticketing-frontend/src/chat/chatTransport.ts`：封装 `/ai-gateway/*` 请求，携带标签页绑定值、会话 ID 和当前登录 token；逐帧解析 SSE 的 `message`、`status`、`context`、`delta`、`complete`、`error` 等事件，并处理连接中断。
- `cinema-ticketing-frontend/src/chat/MessageFeedback.tsx`：点赞、点踩、撤回和补充原因。提交的是消息 ID 与评价，不让浏览器伪造已生成的回答内容。
- `cinema-ticketing-frontend/src/chat/assistant.css`：聊天面板和反馈控件样式。
- `cinema-ticketing-frontend/src/admin/AiFeedbackAdmin.tsx` 与 `ai-feedback.css`：管理员查看、筛选和处理 Dify／内部 Agent 的回答反馈。
- `cinema-ticketing-frontend/src/auth/client.ts` 与 `useTabSession.ts`：登录 token 的前端存取、失效处理及账户切换时的界面隔离；聊天组件依赖这些逻辑。
- `cinema-ticketing-frontend/src/App.tsx`：将聊天组件与后台反馈页面挂入主应用，同时提供统一的业务 API 请求函数。
- `cinema-ticketing-frontend/vite.config.ts`：本地开发时将 `/api` 代理到 Java 8080，将 `/ai-gateway` 代理到网关 8010。

## 2. AI 网关

- `cinema-ticketing-backend/cinema-ai-gateway/app/main.py`：网关入口。`/ai-gateway/session` 建立或恢复聊天；`/chat` 根据模式调用 Dify 或内部 Agent；`agent_events` 先到 Java 解析转接凭证，再把服务端确认的 `user_id` 传给 Agent `/ai/live`。`/stop`、`/reset` 和 `/feedback` 管理对话状态与评价。
- `cinema-ticketing-backend/cinema-ai-gateway/app/store.py`：Redis 中的会话、标签绑定、登录身份验证、历史、频率限制、生成锁和反馈锁。历史记录由服务端取得，浏览器不能直接提供可信身份。
- `cinema-ticketing-backend/cinema-ai-gateway/app/protocol.py`：把上游 SSE 解析为完整事件，并生成浏览器统一使用的 SSE 数据帧。
- `cinema-ticketing-backend/cinema-ai-gateway/app/feedback.py`：保存回答快照；仅用户实际提交评价时调用 Java 持久化。内部 Agent 的反馈标为 `NOT_APPLICABLE`，不会同步给 Dify。
- `cinema-ticketing-backend/cinema-ai-gateway/app/config.py`：网关地址、Dify 密钥位置、内部服务 token、Redis 等配置。密钥只在服务端读取。
- `cinema-ticketing-backend/cinema-ai-gateway/app/__init__.py`：Python 包标记。
- `cinema-ticketing-backend/cinema-ai-gateway/.env.example`：网关本地配置模板，不含实际密钥。
- `cinema-ticketing-backend/cinema-ai-gateway/requirements.txt`、`pyproject.toml`、`Dockerfile`：依赖、项目元信息和容器构建定义。

## 3. 转接和 Java 业务边界

- `cinema-ticketing-backend/src/main/java/com/cinema/ticketing/controller/AiHandoffController.java`：`/api/ai/handoff` 接受当前登录 token 与会话 ID；内部 `/internal/ai/handoff/resolve` 仅接受匹配的内部服务 token。
- `cinema-ticketing-backend/src/main/java/com/cinema/ticketing/service/AiHandoffService.java`：在 Redis 中保存 10 分钟有效的转接凭证，并在解析时重新验证登录状态，返回用户 ID、会话 ID 和 `cinema:read` 范围。
- `cinema-ticketing-backend/src/main/java/com/cinema/ticketing/controller/InternalAiController.java`：Agent 可调用的固定业务接口：影片、场次、本人订单、退票规则、知识检索和推荐。订单查询同时以订单号和可信用户 ID 限定结果；退票资格由当前订单状态与规则计算。接口不执行交易写操作。
- `cinema-ticketing-backend/src/main/java/com/cinema/ticketing/service/AuthService.java`：登录 token 在 Java 侧的校验依据，也用于转接凭证的签发与解析。
- `cinema-ticketing-backend/src/main/java/com/cinema/ticketing/common/SellableScreenings.java`：内部场次查询复用的可售条件。
- `cinema-ticketing-backend/src/main/java/com/cinema/ticketing/common/JdbcTimes.java`：订单查询时的数据库时间类型转换，避免时间字段格式混杂。
- `cinema-ticketing-backend/src/main/java/com/cinema/ticketing/controller/AiGatewayController.java`、`service/AiGatewayService.java`、`dto/AiChatRequest.java`：旧版 Java 转发路径 `/api/ai/chat` 和 `/api/ai/stream`，仍供兼容，当前聊天页面不走这条路径。

## 4. 内部 Agent

- `cinema-ticketing-backend/cinema-ai/app/main.py`：FastAPI 入口、LangGraph 状态图及固定 Java 工具。`/ai/live` 是当前网关使用的实时流接口；先理解意图，再澄清或执行只读工具，最后基于本轮结果生成回复。`/ai/chat` 与 `/ai/stream` 对应旧版兼容路径。
- `cinema-ticketing-backend/cinema-ai/app/intent.py`：问题归一化、规则回退、模型结构化理解、上下文实体提取与缺失参数澄清。模型只在允许的意图和工具范围内工作。
- `cinema-ticketing-backend/cinema-ai/app/model_config.py`：读取 Qwen 模型配置及服务端密钥；无密钥时使用基于真实查询结果的模板回复。
- `cinema-ticketing-backend/cinema-ai/app/failures.py`：将模型和业务 HTTP 错误转换成固定错误码与用户可读信息，避免把凭证或请求内容写入错误日志。
- `cinema-ticketing-backend/cinema-ai/app/__init__.py`：Python 包标记。
- `cinema-ticketing-backend/cinema-ai/knowledge/`：本地影院 FAQ、购票须知和退票规则文本，用于检索补充说明；实时退票资格仍以 Java 当前订单和策略为准。
- `cinema-ticketing-backend/cinema-ai/.env.example`：Agent 本地配置模板，不含实际模型密钥。
- `cinema-ticketing-backend/cinema-ai/requirements.txt`、`pyproject.toml`、`Dockerfile`：依赖、项目元信息和容器构建定义。

## 5. 反馈、配置与部署

- `cinema-ticketing-backend/src/main/java/com/cinema/ticketing/controller/AiFeedbackController.java`：内部反馈写入端点与管理员查询、处理端点。
- `cinema-ticketing-backend/src/main/java/com/cinema/ticketing/service/AiFeedbackService.java`：反馈入库、筛选、审核和 Dify 同步状态更新。
- `cinema-ticketing-backend/src/main/java/com/cinema/ticketing/config/AiFeedbackSchemaInitializer.java` 与 `src/main/resources/ai-feedback-schema.sql`：启动时建立反馈表的定义。
- `cinema-ticketing-backend/src/main/resources/schema.sql`：完整业务库定义，包含 Agent 查询依赖的业务表；它属于共享数据库，并非 Agent 专属库。
- `cinema-ticketing-backend/src/main/resources/application.yml`：Java 的 `ai.service-url` 与 `ai.internal-token` 配置，同时保留共享业务服务的默认设置。
- `cinema-ticketing-backend/start-ai-local.ps1`、`stop-ai-local.ps1`：Windows 本地启动及停止 Agent 和网关；启动脚本使用服务原项目位置和本地虚拟环境。
- `cinema-ticketing-backend/docker-compose.yml`：Java、Agent、网关、Redis、Nginx 等服务的部署连接和环境变量映射。
- `cinema-ticketing-backend/nginx/nginx.conf`：将公开的 `/ai-gateway/` 代理到网关，Java `/api/` 单独代理；没有为 Agent 的 `/ai/live` 配置公网代理。
- `docs/dify-agent-setup.md`：当前启动、模型、凭证、会话和部署说明，恢复时优先参考。
- `docs/dify-agent-options.md`：Dify 与内部 Agent 转接方案比较，含已选方案与后续可选方向；其中的方案设想不能一律视为已实现代码。

## 关键约束

1. `AI_INTERNAL_TOKEN` 必须在 Java、网关和 Agent 三端一致；本地示例值仅用于开发。
2. 网关的 Agent 模式必须使用 Java 解析出的用户身份和会话范围；不能信任浏览器或模型提交的 `user_id`。
3. Agent 的工具只允许查询。下单、支付、退票等状态变更仍由 Java 正式业务 API 处理。
4. 本地知识文本提供一般说明；订单是否可退以 Java 当前返回的 `can_refund`、`refund_reason` 和当前退票政策为准。
