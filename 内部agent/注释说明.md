# 内部 Agent 文件职责与同步说明

下列路径均相对于 `源文件/`。副本与原项目文件保持字节一致，注释集中在此说明；同步机制见 [README.md](README.md)。

## 1. 当前调用链

```text
智能 Agent 窗口 → AI 网关（Agent 通道）→ 内部 Agent 8000
                                             ↓ MCP Streamable HTTP
                                         MCP Server 8020
                                             ↓ 受约束的内部查询接口
                                         Java 8080 → MySQL / Redis
Dify 悬浮球 → AI 网关（Dify 通道）→ Dify
```

网关监听 8010，分别保存两个通道的会话、历史和反馈，不交换两个机器人的对话数据。MCP 在 Docker 中使用内部地址 `http://cinema-mcp:8020/mcp`，本地为 `http://127.0.0.1:8020/mcp`；Java 的 8080 不承载 MCP 协议。

## 2. 内部 Agent、MCP 与知识检索

- `cinema-ticketing-backend/cinema-ai/app/main.py`：Agent HTTP 入口及流式回答编排。
- `app/react_agent.py`、`react_tools.py`、`task_progress.py`：模型工具循环、受约束的工具执行、多步任务状态。
- `app/intent*.py`、`query_semantics.py`、`query_answers.py`：意图、查询条件与结果表达。上映与已排期是不同条件；“今天”按北京时间当天约束。
- `app/mcp_server.py`：电影、场次、座位、本人订单四类只读工具及 MCP 服务身份检查。
- `app/mcp_client.py`、`java_client.py`：MCP 协议客户端及固定 Java 接口访问。内部服务凭证由服务端读取，订单用户身份由可信调用链传递。
- `app/policy_retrieval.py`、`reranker.py`、`knowledge/`：本地知识检索与云端 rerank。通用规则文档不能代替实时订单查询。
- `app/memory*.py`、`memory_worker.py`、`provision_memory_model.py`：长期记忆检索、索引处理和模型准备。实际向量库及模型文件不复制。
- `app/model_config.py`、`glm_router.py`、`agent_budget.py`、`versions.py`、`config/`、`prompts/`：模型、成本/路由策略、版本和提示词。
- `app/tracing.py`、`reflection.py`、`rule_verifier.py`、`failures.py`：调用追踪、反思和失败处理。
- `evaluation/`、`tests/`、`scripts/`：评测源码、回归测试和诊断脚本；生成结果目录按同步配置排除。

以上均基于当前源码职责概括，具体接口和行为以对应源文件及同步文档为准。

## 3. AI 网关与身份边界

- `cinema-ticketing-backend/cinema-ai-gateway/app/main.py`：独立 Dify/Agent 通道、会话操作、流式转发和停止生成。
- `app/store.py`：Redis 会话、身份验证、频率限制、并发生成锁和通道隔离。
- `app/protocol.py`：SSE 数据帧转换；`feedback.py`：反馈及回答快照；`config.py`：配置解析。
- `tests/`：通道、身份和会话生命周期回归检查。

Java 的 `AiHandoff*` 负责转接凭证，`InternalAiController` 负责白名单查询，`AiMemory*` 负责长期记忆的业务持久化，`AiFeedback*` 负责反馈持久化。`AuthService` 和相关用户映射用于账户失效、角色与会话检查。`ai-*-schema.sql` 是 AI 数据表定义；`schema.sql` 和 `application.yml` 是共享后端定义。

持有内部服务凭证的调用方需要先确认用户身份；模型不能自行选择订单所属用户。下单、支付和退款等交易仍通过 Java 正式业务接口完成。

## 4. 前端、配置与使用文档

- `cinema-ticketing-frontend/src/chat/`：Agent 窗口、Dify 悬浮球、消息发送、SSE、反馈和会话恢复。
- `src/auth/`、`src/App.tsx`：登录会话及应用挂载；`src/admin/AiFeedbackAdmin.tsx`：后台反馈管理。
- 两个 Python 服务的 `.env.example`、`requirements.txt`、`pyproject.toml`、`Dockerfile`：配置模板、依赖和镜像定义。
- `cinema-ticketing-backend/start-ai-local.ps1`、`stop-ai-local.ps1`：服务启动和停止；源码副本同步独立运行。
- `docker-compose.yml`、`nginx/nginx.conf`：项目内的部署模板，不代表服务器当前全部启用这些组件。
- `docs/`：同步范围内的 MCP、通道隔离、长期记忆、rerank、Agent 流程和评测说明。

新增匹配文件会自动加入清单；不存在或被重命名的旧文件会退出清单。本说明按模块解释职责，不把历史文件列表当作当前实现。
