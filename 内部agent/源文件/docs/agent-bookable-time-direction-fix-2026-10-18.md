# 可购票推荐时间方向修复

## 问题依据

2026-10-18 22:03（北京时间），用户问“近一周15块钱以下的电影推荐”。

追踪编号：`b393839a-1c12-4640-b5ae-84e02b3dbb8b`。

旧实现通过拼接“可购票场次”将日期目标切换到观影日期，但仍将“近一周”计算为过去七天：2026-10-12 至 2026-10-18。Java 再叠加场次尚未开始的条件，实际只剩当天晚间的场次，导致查询范围不符合购票推荐的默认口径。

## 本次改动

### 时间规则

- `resolve_query_times` 新增显式的默认时间目标和可购票用途参数，移除意图层拼接查询文字的做法。
- 只有可购票用途下、已经确定为观影日期的“近N天／周／月”“最近N天／周／月”，才默认向未来计算，并记录 `assumed_direction`。
- 预算问题的默认时间目标为观影日期；明确“新上映、上映日期、首映”等表达仍按上映日期计算。
- “过去”等明确历史方向不转换为未来；当前可购票用途遇到历史请求时，说明能力边界，不调用查询工具。
- 自然周“本周／这周”的原始日期不变，不自动扩展为未来七天。
- 单独更新预算时保留已经确认的绝对日期，不重新滚动前一轮时间窗口。
- 沿用每轮请求统一的北京时间基准日期。

### 原始范围与有效范围

时间上下文保留原始 `windows`，新增：

- `bookable_only`：是否属于当前可购票用途。
- `effective_screening_date_from`、`effective_screening_date_to`：有效查询日期。
- `bookable_window_issue`：正常、明确历史请求或日期全部过去。

投影工具参数时，将可购票日期与今天及之后取交集。精确到当前时刻的“尚未开始”限制继续由 Java 原有查询执行。完全过去的日期不会被静默替换为今天，也不会发送一个空日期范围查询。

例如，在2026-10-18：

- “近一周15元以内”：默认观影日期2026-10-18至2026-10-24。
- “本周15元以内”：原始自然周2026-10-12至2026-10-18；有效购票日期仅2026-10-18，且场次必须尚未开始。
- “最近一周新上映、15元以内”：上映日期仍为2026-10-12至2026-10-18，同时要求存在当前可购票且符合预算的场次。
- “过去一周15元以内的场次”：说明当前可购票查询不支持历史场次用途，不自动改成未来七天。

### 回答与追踪

- 使用未来默认口径时，回答明确说明该假设。
- 自然周被裁剪时，同时说明原始日期范围和剩余可购票范围。
- 推荐结果再次校验日期，异常结果不能直接组成推荐答案。
- 脱敏追踪保留默认方向标志、有效日期范围和历史范围阻断原因，不增加原始用户表达。
- 时间策略标识更新为 `recommendation-time-v3`。
