# 影院 Agent 真实业务对照评测（2026-10-09）

## 结论

本轮固定开发问题集上，ReAct 的严格任务成功率从 **66.7% 提升到 81.3%（+14.6 个百分点）**，组合任务从 **0/12 提升到 10/12**。工具链正确率提高，但基础题存在退化；响应时间、模型调用和 Token 消耗增加。当前结果支持“增强连续工具查询能力”，不能写成“同时提速降本”。

## 范围与版本

- 固定 24 题：基础查询 12、组合查询 6、缺参追问 4、边界保护 2。每版每题 2 次，共 96 次任务，每版 48 次。
- 旧版直接加载 Git `039085e` 的入口；新版为 `581e103` 的 ReAct。评测期间没有调整产品逻辑或提示词。
- 真实开发 Java / MySQL / Redis / MCP、真实 Qwen3.7 Flash；不是模拟工具或伪造模型结果。
- 并发 1；题序固定种子打乱，新旧执行顺序交替。温度 0、输出上限 2048、关闭思考、关闭长期记忆；ReAct 工具尝试预算 4。
- 题库与业务快照在计分请求前冻结。4 次小规模试跑及连通性探测不计入正式结果。
- 评测后 7 项影片、排期、座位、订单和规则核对一致；仅忽略每次响应变化的订单 `server_time`。

## 四项指标：旧流程 → ReAct

### 1. 任务成功率

- 全部：**32/48（66.7%）→ 39/48（81.3%）**。
- 基础查询：22/24（91.7%）→ 19/24（79.2%）。
- 组合查询：0/12（0%）→ 10/12（83.3%）。
- 缺参追问：6/8（75%）→ 6/8（75%）。
- 边界保护：4/4（100%）→ 4/4（100%）；仅两个固定边界题，不能据此声称全面安全。

这里使用**严格验收成功率**：完整且正确的工具链、参数和可信用户身份、所需关键事实正确、正常结束同时满足。即使最后答案包含正确事实，错误工具尝试、遗漏必要查询或预算耗尽仍可能判失败。因此不能把此指标称为单纯的回答语义准确率。

### 2. 工具调用正确率

- 整题工具链正确率：**36/48（75.0%）→ 43/48（89.6%）**。
- 按题统计选择、参数、顺序及身份是否符合事先声明的允许方案；不是按单次调用统计的准确率。
- 澄清和拒绝题要求不调用业务工具；报告提供分组指标，避免这类题掩盖真实查询错误。

### 3. 响应耗时

- 首字 P50：**1.82 s → 4.32 s**。
- 首字 P95：**2.43 s → 6.72 s**。
- 完整回答 P50：**1.87 s → 4.47 s**。
- 完整回答 P95：**3.55 s → 7.62 s**。

从 `Assistant.live` 入口计时到首个非空答复片段/流结束，状态事件不算首字。完整耗时包括失败；两版各有 1 次无答复，首字各统计 47 个有效样本。启动、登录、网关和浏览器网络不计入。P50/P95 使用线性插值，属于小样本描述统计，不能当作线上 SLA。

### 4. 单次任务成本

- 平均模型调用数：**1.33 → 3.29**（两版总计 64 / 158 次 SDK 逻辑调用）。
- 平均输入 Token：1426.69 → 6239.96；平均输出 Token：170.06 → 296.48。
- 平均总 Token：**1596.75 → 6536.44**，增加到约 4.09 倍。
- 平均缓存输入 Token：976 → 3544。
- usage 缺失调用数：两版均为 **0**；全部使用供应商实际返回值。
- 估算平均任务费用：**¥0.000265 → ¥0.000918**，增加到约 3.46 倍。
- 估算每成功任务费用：¥0.000398 → ¥0.001130；该口径将失败任务消耗也计入总费用。
- 96 次正式任务总估算费用：约 **¥0.056801**，不含试跑和连通性探测。

费用按 [阿里云 Qwen3.7 Flash 官方价格](https://help.aliyun.com/zh/model-studio/qwen3-7-flash) 的北京地域原价与实际缓存命中 Token 估算（核对日期 2026-10-09），不代表账单扣费，未考虑赠送额度或折扣。SDK 内部 HTTP 重试不单独计为模型调用。交替执行缓解顺序差异，但本轮并非冷缓存性能测量。

## 复核与原始证据

逐题复核所需关键事实与工具轨迹，共 8 条人工修正：

- 6 条正确纯数字座位答复（旧版 4 条、新版 2 条）原先被要求附带标签的正则漏判，修正为成功。
- 2 条旧版组合答复仅列场次，规则把场次编号或时间中的数字 5 误识别为退票截止分钟，修正事实检查为失败；这两条原本已因缺少工具调用判失败，成功率不变。
- 自动原判成功率为旧版 58.3%、新版 77.1%；原判不覆盖。没有改题或选择性重跑。

证据目录：`cinema-ticketing-backend/target/agent-evaluation/comparison-20261009/`。这是本地保留、Git 忽略的开发数据目录。

- `cases.json` / `snapshot.json`：固定问题、独立预期工具方案与业务判定依据。
- `metadata.json` / `baseline_main.py`：代码版本、配置、数据哈希、实际旧版入口。
- `trials.jsonl` / `summary.json`：96 次原始答复、工具轨迹、校验、usage、计时及自动原判。
- `review.json` / `reviewed_summary.json`：逐条修正理由与复核后统计。
- `stability.json`：业务数据复核。
- `report.html`：可直接用 Chrome 打开的离线交互报告，支持分组和逐题展开。

## 暴露的问题与后续方向

1. **规则来源冲突**：纯规则题两版两轮均回答开场前 30 分钟，Java 当前规则是 5 分钟。应明确动态业务规则优先级，并同步知识文档。
2. **多订单理解不稳定**：ReAct 两轮中一轮误追问订单号；已有多个订单号的请求仍受单订单理解/校验影响。
3. **循环停止条件不足**：推荐题两轮均发生多余查询及被拒绝的调用；不存在影片题也有一次无效重试。
4. **参数约束冲突**：组合题一轮连续 4 次被拒绝后无答复；需检查理解阶段约束与循环参数校验的一致性。
5. **基础查询开销**：旧版有确定性快速路径，新版加入理解/决策往返。适合评估基础题快速路径与复杂题 ReAct 分流。

本轮只有一个未来可查询座位的场次；两个基础座位题共享场次，逐场查询题实际只有一场。尚未覆盖大量场次遍历、并发、长历史、多轮追问完成率或线上用户分布。这些结果仅适用于本轮固定开发验收集。

## 可用于简历的表述

基于 LangGraph 构建 ReAct 只读工具调用循环，建立覆盖票务查询、组合任务、参数澄清与边界保护的 24 题固定业务验收集，完成新旧流程 96 次真实模型对照评测，将严格任务成功率由 66.7% 提升至 81.3%，整题工具链正确率由 75.0% 提升至 89.6%，组合任务完成率达到 83.3%。

面试时应同时说明：这是固定开发问题集，耗时与费用增加；不得声称线上准确率、提速或降本。
