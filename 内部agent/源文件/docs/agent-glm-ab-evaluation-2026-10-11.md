# Agent 新一轮实测与旧版对比（2026-10-11）

## 1. 结论

完成 **168 题 × 2 轮 × A/B 两组 = 672 次真实任务**。A 关闭 GLM，B 开启 GLM；均使用当前优化代码、真实 Java / MySQL / Redis 数据与 Qwen 接口。

共同 144 题上，B 的任务成功率由上一轮 **88.2% → 96.5%**，变化 **+8.3 个百分点**；平均模型调用变化 **-44.0%**，已观测聊天 Token 变化 **-36.2%**。

完整回答 P50：**3.32 → 0.08 秒**；P95：**7.46 → 7.30 秒**。中位数与长尾分别判断，避免将节省调用直接等同于全面加速。

GLM 共发起 **14 次**真实调用，**0 次**被接纳并接管理解；A/B 任务通过分别 **316/336、316/336**。整体优化效果与 GLM 单独收益需要分开解释。

本轮 GLM 没有成功接管样本，因此不能估计它正常服务时的意图识别准确率或节省幅度；当前数据反映的是开启 GLM 后的回退行为。

本轮完成评测与分析，未在运行中调整业务代码、Prompt 或验收规则。

仍需修复局部回归：标准题整题通过率 99.3% → 98.6%；口语组合题事实验收 95.8% → 91.7%；新增澄清补问题工具链仅 79.2%。整体平均提升不能代替这些子集的验收。

## 9. 失败样本与下一步

### 已核实的原因

1. **口语场次号漏提取**：`Q_X12 / Q_X13` 的‘还有 39 号场’漏识别，任务计划形成无编号座位子任务。已经给出 39 的模型提议可能被守卫拒绝，之后错误追问或停滞退出。检查 `SCREENING_PATTERN` 对前置‘有’的排除条件，改用完整数量语义判断。

2. **时间词跨领域误识别**：`F_S10 / Q_S10 / Q_M05` 的退票‘多少分钟’同时被识别为影片 duration，形成额外 `search_movies` 任务。先按票务规则语境约束字段提取，避免额外任务再把无关结果拼入降级回答。

3. **澄清续接丢查询范围**：日期补问中的 `FOLLOW_screenings_01 / 07` 返回 `bookable`，golden 要求继承此前的 `scheduled`；当前数据两种范围恰好相同，事实检查能通过，但工具参数仍不符合原请求。续接应保留待补槽任务的意图及查询范围，再只更新用户补充槽位。

4. **等价工具计划需审查**：`FOLLOW_screenings_05` 当前用 `search_movies(movie_scope=scheduled)` 返回嵌套排期，golden 只接纳 `search_screenings`，严格工具链评分为失败。该例可能涉及等价方案覆盖不足；本轮未事后改标签、未放宽主指标，后续应先确认分页与场次完整性再增补可接受计划。

5. **检索冲突仍存在**：抽查 `query_ticket_policy` 的知识片段仍有‘开场前 30 分钟’旧内容，而实时 `policy.cutoff_minutes=5`。当前权威字段能约束答案，但冲突来源仍需治理，不能将字段优先级视为知识库已一致。

补充上下文检查覆盖 **88 次**必需查询规则的任务；未找到截止时间上下文中的‘5 分钟’ **0 次**，答案出现‘30 分钟’截止冲突 **0 次**。可只查询本人退票资格、无需解释通用规则的题不纳入该检查；保留原分数，不据此修改主指标。
