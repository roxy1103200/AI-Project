## 1. 已完成的行为修改

- “给我推荐最近一周的电影”按含当天的最近 7 个自然日上映范围直接推荐。以本轮参考日 2026-10-18 为例，范围是 2026-10-12 至 2026-10-18。
- 默认理解明确标记 `assumed_target=true`，答复说明“我先按上述上映日期范围为你推荐”，不再写成用户已经确认。
- 用户不指定题材时，允许空偏好，不强制追问城市或影院。
- 预检与最终处理共用时间策略，避免最终阶段覆盖已解决的时间对象。
- “我是说按观影日期”撤销原默认上映过滤；“我是说这周有票的”改为当前可订购条件。
- “这些电影今晚有票吗”只查询上一轮推荐集合，不猜影片或场次编号；每部影片的有票/无票结果分别标明片名。
- 没有推荐上下文时说“这些电影”，会先请用户补充片名；不能被模型扩展为查询全库场次。
- 只改题材时保留已展示的绝对日期；重新明确“最近一周”时按本轮参考日计算。
- 明确日期无效、同一对象硬条件冲突、缺少订单/场次信息等必要澄清继续保留。
- “上映日期必须在最近一周”不再被拆成额外的影片资料任务。

## 2. 代码与测试入口

业务实现位于 `cinema-ticketing-backend/cinema-ai/app/`：

- `time_normalization.py`：统一默认、继承、纠正和日期恢复策略。
- `intent.py`：复用已验证时间、限制题材误作片名、提取有依据的前轮候选。
- `intent_routing.py`：允许无题材推荐轻路径，避免把推荐中的上映日期当成独立资料查询。
- `task_progress.py`、`react_tools.py`：按前轮候选逐部查场次，拒绝工具擅自替换候选。
- `query_answers.py`：默认口径、真实日期及逐部空场次说明。

评测实现：

- 新增 `evaluation/website_cases_v2.py`，最终共 67 个网站场景；v1 用例及冻结 Golden 数据未覆盖。
- 新增 `evaluation/website_time_policy.py`，根据独立夹具快照评分，不调用被测日期决策函数生成预期。
- `evaluation/website_regression.py` 支持 `--suite v1|v2`，默认仍为 v1；失败、阻塞及无有效用例时非零退出。
- Java 测试夹具增加起止日、范围外、未来、未知日期、下架及不同题材影片，快照保留状态事实。
