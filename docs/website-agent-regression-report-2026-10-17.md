## 实际修复的问题

### 1. “晚上呢”丢失已确认的观影日期

复现：“明天《回归悬疑新片》有哪些场次” → “晚上呢”。原先最终时间归一化没有把仅含时段的短句识别为追问，覆盖了前一步已经继承的“明天”，导致查询扩大为今天及之后的晚间场次。

修复：日期和时段短句共用追问识别；只替换用户本轮明确修改的条件。复测中保留 2026-10-18 以及影片，只新增 18:00 至 24:00 条件；Java 收到的日期和时段一致。新增离线测试覆盖该缺陷。

### 2. 模型把相对日期填进题材偏好

复现：“只看最近一周上映的悬疑电影”。某次模型输出把 `preference` 设为“最近一周上映”，导致数据库按错误的偏好检索，返回空结果，而实际存在符合条件的悬疑片。

修复：推荐意图中，用户明确说出的已识别题材优先于模型生成的偏好；日期由时间归一化单独处理。新增故意返回错误模型计划的测试。最终整体验收通过后，T06 又独立连续复测 **3 次，全部通过**。

### 3. 查询失败被包装成普通完成

复现：用户查询其他账号的订单。Java 正确返回 404，但 Agent 丢失了终止错误，只回复“未取得可确认的查询结果”，并发送正常完成事件。

修复：没有有效业务证据且最终查询失败时，传递明确错误事件；网站将其标为“回答未完成”，不发送正常完成。覆盖订单不属于本人、业务不可用和超时；同时保留合法空结果的正常答复。

### 4. 订单状态与支付、退款事实补齐

- 网站订单列表和内部 AI 订单查询复用同一读取及资格说明逻辑。
- 返回订单、支付、退款状态、退款原因类型、退票资格、截止时间和服务端时间；契约为 `cinema-order-v2`。
- 历史支付流水可作为支付事实来源，不伪造支付单或渠道流水。
- REFUNDING 不再解释为普通不可退；UNKNOWN 明确结果仍在核对，不承诺到账日期。
- UNPAID + CLOSING 不宣布已取消；迟到付款补偿保留订单取消状态，分别解释收款和退款。
- Agent 拒绝关键字段缺失、未知状态和不一致的财务组合。

### 5. 运行证据和持久化

- Java 类、Agent/MCP 源码及提示词、网关源码、前端源码都有各自的启动/构建摘要；回归器从本地构建独立计算期望值。
- 受保护接口记录运行版本和本轮查询参数；未携带内部服务凭证时不能访问。普通聊天正文不增加内部诊断信息。
- 网站 message_id 关联服务请求 ID，再关联 LangSmith trace_id；MCP 和 Java 保留同一服务请求 ID。
- 网关保存经过白名单裁剪的时间摘要、运行版本及调用计数；正常完成须在历史保存成功后发送，租约失效不能报告持久化成功。

## 验收覆盖

### 时间与多轮：14 个场景

T01–T08 覆盖本周上映、最近七天软偏好、可购票观影范围、明晚、下周排期、硬性上映条件、不合法日期和空结果。

D01–D06 覆盖上映/观影对象澄清、题材继承、下周追问、晚间追问、软偏好保留和 reset 清理。澄清轮不发出业务查询。

本轮业务参考日为 **2026-10-17，北京时间**：本周 10/12–10/18，最近七天 10/11–10/17，明天 10/18，下周 10/19–10/25。预期日期随每轮实际业务参考日计算。

### 订单：12 个场景

O01–O12 覆盖未付款、关单中、取消未收款、可退、超过截止、已验票、退款 PENDING、退款 UNKNOWN、已退款、取消后补偿中、补偿完成，以及同一会话 REFUNDING → REFUNDED 后重新查询。

每项都把实际答复与独立测试夹具的预期状态核对，同时比较网站订单列表与内部 AI 订单事实。退款未确认时，没有宣布退款成功或到账。

### 身份与结束：6 个场景

S01–S06 覆盖他人订单、过期转接、账号切换、Java 不可用、未知订单契约，以及上游 SSE 截断、主动停止、正常单次完成和历史恢复。

### 浏览器：6 个代表场景

- B01：模糊“这周的悬疑电影”先询问时间对象，选择“有票的”后显示观影日期。

- B03：退款 UNKNOWN 显示处理中、票暂不可使用、不要重复申请及无法确认到账时间。
- B04：取消订单的迟到付款显示补偿退款核对中。
- B05：退出 A 后清理面板与订单；B 恢复自己的空聊天，仅看到自己的订单；查询 A 的退款订单被拒绝。
- B06：生成后立即点击停止，页面显示“已停止回答 / 回答未完成”；未知契约显示失败并可重试。

## 数据与边界

- 使用独立 H2、独立 Redis、独立端口、两个测试账号、三部虚构影片及十四张测试订单。支付能力关闭，未执行付款、退款、锁座或下单操作。
- 只在测试夹具内推进指定订单的退款状态；没有向原网站数据库添加或修改业务记录。
- Golden v1 保持冻结，新增网站用例独立维护。
- 推荐工具沿用项目既有的 Agent → Java 只读调用；订单、影片、场次等 MCP 工具保留 MCP → Java 路径。没有为了测试新增模型写工具。
- 隔离库没有 MySQL 的 DATE_ADD 等函数，首页片单/日程的既有 SQL 出现兼容错误。本轮浏览器结论限于 Agent 面板和订单读取，**不代表整站首页功能验收通过**；未为此修改生产 MySQL 查询。
- 部分真实模型核对会给出保守的“可能尚未覆盖全部要求”附注。通过结果基于日期、参数、业务事实、身份、结束状态等明确断言，不代表所有生成措辞完全稳定。
- 跨日、跨周边界由固定时钟离线测试覆盖；本轮没有修改网站系统时间，也没有声称进行了跨午夜的实时长时间观测。
