# 经营报表：使用与升级

管理员登录后，在桌面或手机的管理菜单选择“经营报表”。默认查询北京时间最近七个自然日，可选择起止日期（均包含），最长 31 天，并按影院、影片筛选。所有汇总、明细及导出明确标记“模拟支付数据”。

## 统计规则

- “销售与退款”：支付金额、毛售出票数按支付日；退款金额按实际退款处理日。窗口净额等于范围内支付流水金额减范围内退款流水金额，可以为负数。已退票订单保留历史支付及毛售出票数。
- “场次与上座率”：按场次开场日计入，包括跨午夜场次；取消场次排除。有效票要求父订单 `ISSUED`，票项 `ISSUED`（兼容 `VALID`）；已验票仍计入。上座率是销售占座比例，不等同于实际到场率。
- 整体上座率为总有效票数除以总容量，按容量加权；范围内任一场次容量未知时，整体上座率显示“—”，逐场次仍可查看有快照的比例。零容量/无场次也不伪造 0%。热门场次仅列有效票数大于零的前十场，按有效票数、上座率降序，同值按开场时间及 ID 排序。
- 历史交易不随影片停售、影院停用而退出销售统计。

## 可售容量快照

采用当前票务业务口径：一个 `seat` 记录计一个可售票位，包含 STANDARD/VIP/COUPLE 类型；类型是标识，当前没有一座多票规则。只计 `AVAILABLE`，排除 `DISABLED`。

首次成功锁座事务中，后端在影厅行锁保护下，将可售座位数量写入 `screening_capacity_snapshot`，随后锁座失败时该写入随事务回滚。已有订单但缺少快照的旧场次保持容量未知；不使用当前影厅座位数回填精确历史。直接创建订单的路径同样尝试捕获快照。

有未结束且已固定容量的场次时，该影厅拒绝新增、删除、补齐、移动、启停或变更座位类型。已有快照的场次拒绝修改/删除排期，即使最初的 Redis 锁已过期。放映结束后可以调整影厅座位，历史快照保持不变。

## 接口与导出

均通过 `X-Auth-Token` 调用，服务端实时执行管理员鉴权。两个日期参数必填，可选 `cinemaId`、`movieId` 为正整数。

```text
GET /api/admin/reports/sales?from=2026-10-01&to=2026-10-07
GET /api/admin/reports/occupancy?from=2026-10-01&to=2026-10-07
GET /api/admin/reports/sales/export?from=2026-10-01&to=2026-10-07
GET /api/admin/reports/occupancy/export?from=2026-10-01&to=2026-10-07
```

JSON 接口使用项目的 `ApiResponse` 包装，`data.metadata` 包含日期范围、`Asia/Shanghai`、`SIMULATED`、`CNY`、生成时间和指标日期口径；`data.summary` 是总计，`data.items` 是明细。场次接口另外返回 `data.popular`。金额使用十进制字符串；上座率为 0～1 的数值或 `null`，前端格式化为百分比。

销售 CSV 按资金事件导出，一行对应一条支付或退款记录。同一订单可以跨行，但金额不会因票项联表重复；退款事件的毛售出票数字段为 0，订单票项数字段仅供核账参考。导出包含事件时间、来源记录 ID、订单号、流水号、影院/影片/场次、金额、票数及状态，不含用户电话和密码。场次 CSV 包含分子、容量、容量来源及比例。

CSV 使用 UTF-8 BOM 和标准引号转义，文本公式前缀加保护。销售导出最多 50000 个资金事件，在同一可重复读事务中每页读取 500 行后生成有界文件；超过上限返回错误，要求缩小筛选范围。场次接口/导出最多 20000 场。请求成功下载的是当前已查询条件对应的明细；账户离开或筛选变化会取消未完成的导出。

## 数据库升级与启用

新版本后端启动时默认运行 `SalesReportSchemaInitializer`，只新增报表表/字段/索引并转换退款时间，不重放基础种子数据：

1. 建立容量快照表。已有场次不批量补造容量。
2. 给 `refund_record` 新增北京时间 `refunded_at DATETIME`；旧 `created_at TIMESTAMP` 通过瞬时时间转换到北京本地时间，兼容 MySQL 会话时区为 UTC 或 UTC+8。
3. 新退款显式写入北京时间 `refunded_at`；新支付显式使用北京时间写入 `paid_at`。历史支付时间原样保留，沿用项目既定的北京业务时间约定。
4. 增加支付和退款的状态/时间/订单联合索引。启动升级由 MySQL 命名锁串行化，并检查字段、索引是否已有，支持重复启动。

请停止旧 Java 进程后启动新版本，避免旧版本继续写入没有 `refunded_at` 的退款。关闭自动升级可设置环境变量 `REPORTS_INITIALIZE_SCHEMA=false`（对应 `reports.initialize-schema=false`），并由运维提前执行等效的单次升级脚本 [20261010-sales-report.sql](../cinema-ticketing-backend/migrations/20261010-sales-report.sql)。手工脚本不可直接重复执行已存在的字段/索引语句。

本地构建与启动：

```powershell
cd E:\development\AI-Project\cinema-ticketing-frontend
npm.cmd run build
cd ..\cinema-ticketing-backend
.\start-local.ps1
```

开发用 Vite 页面会自动加载源码；使用静态部署时需要同步新的 `dist`。报表只依赖 Java/MySQL，不需要重启 Agent、MCP 或网关。部署环境必须使用自身正确的数据库连接配置。

`start-local.ps1` 默认加载 `local` 配置；本次检查中该配置指向的 `192.168.100.133` 数据库不可达，因此未启动该环境的完整服务，也未执行远程部署。启用前请确认该数据库及现有 Redis/RabbitMQ 配置可以连接。
