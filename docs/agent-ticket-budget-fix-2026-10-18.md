## 本次实现

### 预算识别与上下文

- 新增 `max_ticket_price`（两位小数字符串）和 `price_upper_inclusive`。
- 支持“15块钱以内”“不超过15元”“预算15元”“低于15元”等阿拉伯数字表达。
- “以内、以下、不超过”包含上限；“低于、不到、少于”不包含上限。
- 预算由规则提取，模型不得生成或替换预算值，也不得将预算重新放入题材偏好。
- “那20元呢”“改成20元”等明确预算追问承接前轮有效日期、题材、影片和影院条件。
- “不限制价格了”等表达清除价格限制，保留有效上下文。
- 负数、超过两位小数或超过金额上限的数字预算要求用户补充有效金额。

### 时间与查询路径

- 有预算的影片筛选统一使用推荐查询，价格关联实际可购票场次。
- 未明确“上映、新片、首映”时，预算问题的时间按观影日期解析；支持“这一周”的写法。
- 明确上映日期时，仍保留上映日期条件，同时要求存在符合预算的可购票场次。
- 没有日期时查询当前可购票的今天及之后场次，不凭空添加“本周”条件。
- 简单预算推荐使用单个推荐任务，不额外添加一次未带价格条件的场次查询。

### Java 查询

- 新增预算入口 `/internal/recommendations/budget`，保留原 `/internal/recommendations`。
- 新版 Agent 的预算请求使用新入口。旧 Java 不支持时返回查询能力不匹配，不能将其解释成无符合条件的影片。
- `BigDecimal` 处理票价边界，参数化 SQL 使用 `s.price <= ?` 或 `s.price < ?`。
- 价格、影院和观影日期过滤在选出前五部影片之前执行。
- 影片资格与展示场次复用同一筛选条件，避免影片匹配但展示超预算场次。
- 票价口径是场次票面价格，不计算优惠券、会员折扣或订单最终实付金额。

### 返回校验与回答

- 预算查询必须返回对应场次和价格证据，缺失证据或场次超预算即拒绝使用结果。
- 展示预算口径、有效观影日期、影片、影院、场次时间和票价。
- 空结果说明未找到同时满足预算及其他条件的可购票场次，不再建议“换一个题材”。
- 不自动提高预算或扩大日期。
- 追踪增加 `ticket_budget` 条件存在标志、预算路由原因，实际 Java 调用记录价格参数；不新增原始对话到脱敏追踪。
