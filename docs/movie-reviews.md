# 影评、互动与验票

## 资格与角色

- 管理员可以作为购票观众发表个人影评，与普通观众使用相同资格：当前持有该影片已出票有效票，且所购场次放映结束或该票已验票。有效票兼容历史 VALID，支付正常产生的票项状态为 ISSUED。
- 放映结束时间为开场加影片时长；影厅占用结束时间还包含 20 分钟周转，不能用于影评的观影时间判断。业务时间统一为北京时间。
- 登录即可点赞、举报或回复，不要求购票；游客可以阅读已审核公开内容。不能点赞或举报自己的内容。
- 管理员可以审核所有影评和回复，包括自己的内容；操作人、内容版本和处理结果保留审计记录。管理员身份不豁免个人影评的观影资格，也不提高个人评分权重。

## 影评状态

- PENDING：新提交或修改后的内容，只有作者和管理员可读。
- APPROVED：审核通过；影评还要满足观影资格才公开，回复还要满足原影评公开才公开。
- REJECTED：审核拒绝，保留内容和拒绝原因，作者具备资格时可修改影评重新送审。
- HIDDEN：管理员隐藏违规内容；影评和相关公开评分退出，回复也停止展示。原地修改不能解除隐藏，管理员可恢复或转回待审核。

每人每片一条影评，1～5 星和非空正文，最多 1000 字。修改会重新送审。影评均分与计数只包含公开影评；无公开评分时显示“暂无评分”。作者可删除自己的内容，删除影评同时删除关联回复、点赞和举报；已存在的审核操作快照保留，供数据库审计。

审核通过和转回待审核无需说明，API 允许省略 note、null 或空字符串；可选说明最多 1000 字。拒绝或隐藏必须提供 1～1000 字非空白原因。回复正文必须为 1～1000 字非空白内容，与审核说明是不同字段。通过依据是管理员对正文是否符合社区规范的人工判断，不依据说明字数或星级高低；举报结案说明仍必填。

## 互动

- 点赞绑定影评和账户，PUT 设置点赞状态，重试不重复累加；修改影评不清空已有点赞。点赞不影响星级评分。
- 回复是一层讨论，没有嵌套楼层或评分。登录账户在每条影评最多保留 20 条回复，回复同样先审核；管理员回复显示身份标记。
- 回复作者可在影片详情“我的回复”查看最近 20 条，包括原影评未公开时的回复；公开影评内的回复列表分页，同时返回当前用户本人的未公开回复。
- 举报保存目标内容版本、正文快照、原因和说明，同一账户同一版本幂等。正文或审核状态变更产生新版本，允许再次举报。
- 举报不会自动封禁内容。管理员填写说明后可驳回、处理，或“隐藏内容并处理举报”；后者在同一数据库事务执行。
- 审核操作带页面读取到的 revision，内容被修改或其他管理员已处理时返回 409，需刷新后重新判断。处理记录包含操作人、时间、前后状态和内容快照。

## 验票与退款

后台“验票入场”按订单号核对购票人、影片、影院、影厅、场次和座位，然后选择实际到场票项确认。仅允许在开场前 15 分钟至放映结束验票。取消场次、未出票、取消和退票票项不能验票。首次时间和操作人记录在每个票项，重复操作不覆盖。

验票和退款都先锁住订单，因此同一订单不能同时验票和退款。任何票项已验票时整单不可退票（当前系统没有部分退款）。观众订单列表的退票按钮和内部 Agent 的退票资格响应遵循这一条件。

## 页面与接口

- 影片详情：评论表单、本人审核状态、点赞、回复、举报、我的回复。
- 后台下拉菜单 → 影评管理：影评审核 / 回复审核 / 举报处理。
- 后台下拉菜单 → 验票入场：查询订单并按座位验票。

公开和本人接口：

- GET/PUT/DELETE `/api/movies/{movieId}/reviews`。
- PUT `/api/movies/{movieId}/reviews/{reviewId}/like`，请求 `{liked: true/false}`。
- GET/POST `/api/movies/{movieId}/reviews/{reviewId}/replies`；DELETE 同路径 `/{replyId}`。
- POST `/api/movies/{movieId}/reviews/{reviewId}/reports`；回复举报为 `/replies/{replyId}/reports`。

管理员接口（全部要求 ADMIN 登录）：

- GET `/api/admin/movie-reviews`，kind/status/query/page 筛选，20 条/页。
- PUT `/api/admin/movie-reviews/{REVIEW|REPLY}/{id}`，revision/status/note。
- GET 同路径 `/history`，最近 50 条处理记录。
- GET `/api/admin/movie-reviews/reports`，status/page 筛选。
- PUT `/api/admin/movie-reviews/reports/{id}`，status/note/hideTarget/revision。
- GET `/api/admin/tickets/{orderNo}`；POST 同路径 `/check-in`，`itemIds` 为票项 ID，最多 6 张。

## 数据升级与启动

重启 Java 后端会执行 `MovieReviewSchemaInitializer`，使用数据库升级锁检查并补充已有表字段、创建互动表，不重跑种子或改变场次/订单时间。已有影评正文保留，新增 status 默认 PENDING，需管理员审核后公开；未验票的票不会伪造验票记录。

新数据库的 `schema.sql` 包含完整新结构。若部署账户没有结构变更权限，可由数据库管理员先执行一次 `migrations/20260927-review-community.sql`，再设置 `reviews.initialize-schema=false`。该手动脚本用于升级旧结构，不应在已升级的库重复执行；结构升级器本身支持重复启动。

前端源码开发服务刷新页面即可；静态部署需更新本次构建的 dist。Dify、AI 网关与内部 Agent 的模型配置没有变更。
